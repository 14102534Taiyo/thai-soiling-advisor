# การสำรวจแหล่งข้อมูลทางเลือก (สำหรับใช้อ้างอิงในรายงาน)

บันทึกการค้นคว้าแหล่งข้อมูลอื่นๆ ที่พิจารณาระหว่างพัฒนาโปรเจค แยกตามหมวด
พร้อมผลสรุปว่าทำไมใช้/ไม่ใช้ — เก็บไว้เป็นหลักฐานประกอบหัวข้อ "ข้อจำกัด"
และ "งานต่อยอด" ในรายงาน ไม่ใช่ส่วนหนึ่งของโค้ด/แดชบอร์ด

---

## 1. ความเข้มแสง/รังสีดวงอาทิตย์ (Irradiance)

ปัจจุบันใช้ **Open-Meteo Forecast API** (auto "best_match" model) เป็นแหล่งเดียว
ทดสอบความแม่นยำด้วยการเทียบกับ NASA POWER (ดูหัวข้อ 1.1) พบว่าไม่มี bias
เชิงระบบ แต่รายวันคลาดเคลื่อนได้ ~16% (MAE) เพราะพยากรณ์เมฆผิดตำแหน่ง/เวลาได้

| แหล่ง | สถานะ | เหตุผล |
|---|---|---|
| **Solcast** | ไม่ใช้ — ต้องสมัคร | satellite (Himawari-8/9) nowcast จริง ใกล้เคียง real-time ที่สุดที่หาได้ แต่ต้องสมัครบัญชี (ฟรีสำหรับ student/researcher ผ่านอีเมลมหาลัย) ไม่มี endpoint แบบไม่ต้องสมัคร |
| **NASA POWER** | ใช้เพื่อ *validate* เท่านั้น | ฟรี ไม่ต้อง key แต่ข้อมูลดีเลย์ 2-3 วัน ใช้แทนค่า "วันนี้" ไม่ได้ ใช้ทดสอบย้อนหลัง 27 วันที่กรุงเทพฯ ได้ MAE 0.59 kWh/m² (~16%), RMSE 0.81, r=0.78, mean bias +0.04 (แทบไม่มี bias เชิงระบบ) วันที่แย่สุด (23 ก.ค. 2026) สองแหล่งต่างกัน >2 เท่า |
| **PVGIS** (EU JRC) | ไม่ใช้ | สำหรับพื้นที่ไทยใช้ฐาน **PVGIS-ERA5** (ไม่ใช่ SARAH2 satellite ที่ใช้เฉพาะยุโรป/แอฟริกา) — ความแม่นยำเทียบเท่า ERA5 ทั่วไป ไม่ได้ดีขึ้นกว่า NASA POWER และข้อมูลจำกัดแค่ปี 2005-2020 เท่านั้น (`seriescalc` API คืน error ถ้าขอปีหลังจากนั้น) ใช้ validate ค่าปัจจุบันไม่ได้เลย |
| **DEDE** (กรมพัฒนาพลังงานทดแทนฯ) | ไม่ใช้ | มีข้อมูลความเข้มรังสีจริงจาก 38 สถานีทั่วประเทศ (dataset `sed01` ที่ `pei.dede.go.th`) แต่เป็น**ค่าเฉลี่ยรายปีเดียว (2560/2017)** ไม่ใช่รายวัน ดาวน์โหลด Excel/PDF เท่านั้น ไม่มี API ใช้แก้ค่ารายวันไม่ได้ |
| **TMD** (กรมอุตุนิยมวิทยา) | ไม่ใช้ | มีสถานีวัด "ความยาวนานแสงแดด" (sunshine duration, ชม./วัน) 127 สถานี แต่เป็นหน่วยคนละแบบกับ GHI (W/m²) ต้องแปลงผ่านสูตร Angström-Prescott เพิ่ม (โมเดลอีกชั้น ต้อง calibrate เอง) และ API ต้องติดต่อขอผ่านอีเมล ไม่ self-serve |
| **GISTDA** | ไม่ได้ตรวจสอบลึก | อ้างมี 600+ indicators ผ่าน Spatial Data Service (`sds.gistda.or.th`) แต่เว็บเป็น JS-rendered ตรวจสอบเนื้อหาจาก WebFetch ไม่ได้ ต้องเข้าเบราว์เซอร์จริงถึงจะรู้ว่ามีข้อมูลรายวันหรือ API ไหม — ยังเป็นคำถามเปิด |

### 1.1 ผลทดสอบ NASA POWER vs Open-Meteo (Bangkok, 27 วัน ก.ค.-ส.ค. 2026)

| ตัวชี้วัด | ค่า |
|---|---|
| ค่าเฉลี่ย | NASA POWER 5.08 vs Open-Meteo 5.12 kWh/m²/วัน |
| Mean bias | +0.04 kWh/m² |
| MAE (รายวัน) | 0.59 kWh/m² (~16%) |
| RMSE | 0.81 kWh/m² |
| Correlation (r) | 0.78 |

## 2. ฝุ่น PM2.5/PM10

**ใช้งานจริงแล้ว** — Air4Thai (real-time, `air4thai.pcd.go.th`) + PCD Open Data
Catalog (ย้อนหลัง, `pcd.gdcatalog.go.th`, dataset `12_02_aaq_pm2-5_bkk_metro`)
ทั้งสองฟรี ไม่ต้อง key ตรวจสอบแล้วครอบคลุมทั้ง 5 จังหวัดในดรอปดาวน์ (ชื่อ
dataset บอกแค่ "กรุงเทพฯและปริมณฑล" แต่เนื้อหาจริงกว้างกว่านั้น)

### 2.1 GISTDA ("เช็คฝุ่น" pm25.gistda.or.th) — ตรวจสอบแล้ว 2026-08-15

เว็บเป็น JS-rendered (React SPA) เหมือนที่บันทึกไว้ตอนแรกว่า WebFetch อ่านเนื้อหา
ไม่ได้ — แต่เปิดด้วย headless browser จริง (Playwright) แล้วดักจับ network
request เจอ REST API ที่ไม่มี auth ซ่อนอยู่หลัง JS:

- `GET /rest/getAvailableCSVDownloadDate` → ช่วงข้อมูลจริง **2024-01-01 ถึงวันนี้**
- `GET /rest/getProvName` → รายชื่อ+รหัสทุกจังหวัดทั่วประเทศ (ไม่ใช่แค่ กทม.และปริมณฑล)
- `GET /rest/getPM25by24hrsProvinceAsCSV?dt1=YYYY-MM-DD&id=<prov_id>` → CSV
  **รายชั่วโมง** (24 แถว/วัน) มีทั้งค่าจริงรายชั่วโมงและค่าเฉลี่ยเคลื่อนที่ 24 ชม.
  ทดสอบแล้วสำหรับกรุงเทพฯ (`id=10`) และขอนแก่น (`id=40`) ทั้งวันที่ปัจจุบันและ
  ต้นช่วงข้อมูล (15 ม.ค. 2024) ได้ค่าสมเหตุสมผล
- `GET /rest/getPM25by1dProvinceAsCSV?dt1=YYYY-MM-DD&id=<prov_id>` → ค่าเฉลี่ย
  รายวันเดียว (1 แถว)
- น่าจะมี endpoint แบบ 1 เดือนด้วย (ปุ่ม "รายวัน (1 เดือน)" ในหน้าเว็บ) ยังไม่ได้
  แกะรูปแบบ URL ที่แน่ชัด

**จุดเด่นเทียบกับที่ใช้อยู่**: ครอบคลุมทุกจังหวัด + รายชั่วโมง — แก้จุดอ่อนของทั้ง
CAMS (หยาบ ~40 กม.) และ Air4Thai (รายวันเท่านั้น, ลึกพอแค่กรุงเทพฯ) พร้อมกัน

**ข้อจำกัด**: ย้อนหลังได้แค่ปี 2024 เป็นต้นมา (สั้นกว่า Air4Thai ที่กรุงเทพฯ มีถึง
2011) และเป็นค่าระดับ**จังหวัด** (แบบจำลองผสมดาวเทียม Himawari + สถานีภาคพื้น
ตามที่ GISTDA โฆษณา) ไม่ใช่ค่าระดับสถานีเดี่ยวแบบ Air4Thai — ยังไม่ได้ตรวจสอบว่า
วิธีผสมข้อมูลของ GISTDA เองมี bias เท่าไหร่เทียบกับ Air4Thai ground truth
(ควรเทียบแบบเดียวกับที่ทำกับ CAMS ก่อนเชื่อถือ 100%) และเป็น undocumented
API ที่เจอผ่าน reverse-engineering หน้าเว็บ ไม่ใช่ API ทางการที่มีสัญญา
เสถียรภาพ — อาจเปลี่ยน/ปิดได้โดยไม่แจ้งล่วงหน้า

## 3. ปริมาณฝน (Rain ground-truth)

ปัจจุบันใช้ Open-Meteo ล้วน: **forecast** สำหรับวันนี้/อนาคต, **historical
archive** (ERA5/ERA5-Land/ECMWF IFS reanalysis — *ไม่ใช่* CAMS ซึ่งใช้เฉพาะฝั่ง
PM) สำหรับข้อมูลย้อนหลัง — ระบบจะดึงข้อมูล "วันนี้" ใหม่จาก archive
โดยอัตโนมัติในการรันครั้งถัดไปเมื่อวันนั้นกลายเป็น "เมื่อวาน" (self-correcting
แต่มี delay 1 วัน) ดูกลไกนี้ในแดชบอร์ด (แท็บ "เกี่ยวกับโมเดล", คำเตือนกล่อง
เหลืองเมื่อการรีเซตล่าสุดยังไม่ยืนยัน)

รายละเอียดฝนสำคัญเป็นพิเศษเพราะเป็น**จุดรีเซตของ soiling ratio** — พยากรณ์ผิด
ทำให้ระบบเข้าใจผิดว่าแผงถูกล้างทั้งที่ไม่ได้ล้างจริง กระทบค่าที่คำนวณของทุกวัน
ถัดไปจนกว่าจะถึงการรีเซตครั้งหน้า

| แหล่ง | สถานะ | เหตุผล |
|---|---|---|
| **TMD** (กรมอุตุนิยมวิทยา) | ไม่ใช้ | มี 127 สถานีวัดฝนมาตรฐาน (WMO synoptic) แต่ API ต้องติดต่อขอผ่านอีเมล/โทรศัพท์ ไม่มีระบบสมัครอัตโนมัติ |
| **ThaiWater / HII (สสน.)** — `thaiwater.net` | ไม่ใช้ตอนนี้ (**ศักยภาพสูงสุด**) | เครือข่ายสถานีวัดฝนจริง **950 สถานี** ทั่วประเทศ (มากกว่า Air4Thai) วัดทุก 10 นาทีตอนฝนตก มี "API สำหรับนักพัฒนา" ตามที่โฆษณาไว้ **แต่** เว็บเวอร์ชันใหม่ (`twa.thaiwater.net`) สร้างด้วย Next.js React Server Components ไม่ใช่ REST API แบบเปิดตรงๆ (ตรวจสอบ network requests จริงในเบราว์เซอร์แล้วเจอแต่ `_rsc=` fetches ไม่ใช่ JSON endpoint สาธารณะ) การดึงข้อมูลจริงต้อง reverse-engineer ซึ่งเสี่ยงพังเมื่อเว็บอัปเดต |
| **กรมชลประทาน (RID)** | ไม่ใช้ | ทดสอบพบ API จริงที่ใช้งานได้ไม่ต้อง key: `https://app.rid.go.th/reservoir/api/dam/public/` (คืน JSON ข้อมูลอ่างเก็บน้ำ 35 แห่ง, HTTP 200 ยืนยันแล้ว) พิสูจน์ว่า RID มีสไตล์ API ที่เป็นมิตรกับนักพัฒนา **แต่**เป็นข้อมูลอ่างเก็บน้ำ ไม่ใช่สถานีวัดฝน ลองเดา sibling path หลายแบบ (`/reservoir/api/rain/public/`, `/rainfall/public/` ฯลฯ) ได้ 404 ทั้งหมด — น่าจะมี endpoint ฝนอยู่จริงแต่ path ไม่ตรงกับที่เดา ต้องมีเอกสารภายในหรือถามคนที่รู้จริง |
| **ศูนย์ปฏิบัติการน้ำอัจฉริยะ RID** (`wmsc.rid.go.th`) | ไม่ใช้ | เว็บเก่า โหลดข้อมูลฝนเป็นรูปภาพ (banner PNG) ไม่ใช่ JSON ดึงอัตโนมัติไม่ได้ |
| **hyd-app-db.rid.go.th** (Real-time Hydro data) | ไม่ได้ตรวจสอบ | เจอชื่อจากผลค้นหาว่ามี แต่โดเมนเปิดไม่ได้ในเบราว์เซอร์ทดสอบ (ปัญหา cert หรือ block) ยังเป็นคำถามเปิด |
| **aqi.in** | ไม่ใช้ | ผู้ใช้ทั่วไปเข้าถึงได้ผ่านเว็บ (`aqi.in/weather/th/...`) แต่ (1) API ต้องติดต่อฝ่ายขาย ไม่ self-serve (2) ไม่เปิดเผยแหล่งข้อมูลต้นทาง ไม่รู้ว่าเป็นสถานีจริงหรือโมเดลพยากรณ์อีกเจ้า — ทดสอบเทียบฝนวันเดียวกันที่ระยอง (aqi.in บอก 10.28mm, Open-Meteo บอก 5.00mm) พบว่าต่างกันเกือบเท่าตัว ยืนยันว่าเป็นคนละโมเดลกัน ไม่ใช่ ground truth ที่ยืนยันได้ |
| **HII (สสน.) 6-month rainfall forecast** (`data.hii.or.th`) | ไม่ใช้เป็นแหล่งหลัก — เก็บไว้สำหรับ seasonal context | CSV ดาวน์โหลดตรงได้ ไม่ต้อง API key, license CC BY-NC, ครอบคลุม**ครบ 77 จังหวัด** (ดีกว่า RainRegions ที่มีแค่ 36) ออกพยากรณ์ทุกเดือนล่วงหน้า 6 เดือนด้วย ML จาก climate indices (เช่น ENSO/IOD) **แต่ granularity เป็นรายเดือนเท่านั้น** (ค่าเดียวต่อจังหวัดต่อเดือน เช่น กรุงเทพฯ ม.ค. 2026 = 21.6mm) ไม่แตกเป็นรายวัน/ชั่วโมง จึงบอกไม่ได้ว่าฝนตกกระจายสม่ำเสมอหรือกระจุกวันเดียวถึงเกณฑ์ล้างแผง — ใช้แทน forecast รายวันที่ขับเคลื่อนโมเดล soiling ไม่ได้โดยตรง แต่มีศักยภาพเสริมเป็น seasonal outlook (เช่น ปรับ `deposition_velocity` ตามฤดูกาลให้ละเอียดกว่า 2 ค่าปัจจุบัน หรือแสดงแนวโน้มเดือนหน้าในแดชบอร์ด) |

## สรุปสำหรับหัวข้อ "งานต่อยอด" ในรายงาน

เรียงตามศักยภาพจากมากไปน้อย:

1. **GISTDA "เช็คฝุ่น" (สำหรับฝุ่น PM2.5 โดยเฉพาะ)** — พร้อมใช้งานที่สุดในบรรดา
   ทางเลือกทั้งหมด เพราะเจอ endpoint จริงที่ใช้งานได้แล้ว (ดูหัวข้อ 2.1) ไม่ต้อง
   รอติดต่อใคร ไม่ต้องขอ key — จุดที่ต้องทำต่อก่อนใช้จริง: (ก) เทียบ bias กับ
   Air4Thai ground truth แบบเดียวกับที่ทำกับ CAMS ก่อนเชื่อ, (ข) เป็น undocumented
   API ควรมี fallback ถ้า endpoint เปลี่ยน/ปิดกะทันหัน
2. **ThaiWater/HII (950 สถานีฝน)** — ข้อมูลดีที่สุดที่มีอยู่จริงในไทยสำหรับฝน ปัญหาอยู่ที่
   การเข้าถึงทางเทคนิค (เว็บใหม่ไม่มี REST API เปิด) ถ้าติดต่อ HII โดยตรงหรือหา
   เอกสาร API ภายในได้ น่าจะเป็นตัวแก้ปัญหา "ฝนพยากรณ์ผิด" ได้ดีที่สุด
3. **กรมชลประทาน (RID)** — พิสูจน์แล้วว่ามี API แบบเปิดจริง (เจอ endpoint เขื่อน)
   มีโอกาสสูงที่จะมี endpoint ฝนอยู่จริงเช่นกัน แค่ยังไม่เจอ path ที่ถูกต้อง
4. **Solcast** — สำหรับแสง/irradiance ถ้าต้องการความแม่นยำระดับ nowcast จริง
   สมัครฟรีได้ด้วยอีเมลมหาลัย (student/researcher tier)
5. **TMD** — มีข้อมูลครบทั้งฝนและแสง (sunshine duration) แต่ต้องขอ API
   ผ่านช่องทางราชการ ใช้เวลานานกว่าจะได้ access
6. **HII 6-month rainfall forecast** — ครอบคลุมครบ 77 จังหวัด ไม่ต้องขอ key แต่
   granularity รายเดือนเท่านั้น ใช้แทนฝนพยากรณ์รายวัน/ชั่วโมงที่ขับเคลื่อนโมเดลไม่ได้
   เหมาะเป็น seasonal context เสริมมากกว่าแหล่งข้อมูลหลัก
