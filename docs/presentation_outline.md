# โครงสร้างสไลด์นำเสนอ (~10 นาที)

ร่างจากเนื้อหาโปรเจคจริงทั้งหมด (โค้ด, ผลทดสอบ, การ validate, แดชบอร์ด) — ตัวเลขทุกตัวดึงมาจากการรันจริง
ไม่ใช่ตัวเลขสมมติ ปรับคำพูด/ตัดต่อได้ตามสไตล์การพูดของตัวเอง

**จังหวะเวลา**: ~13 สไลด์เนื้อหา (ไม่รวมปก) เฉลี่ยสไลด์ละ ~45-60 วินาที

---

## สไลด์ 1 — ปก (ไม่นับเวลา)
ชื่อโครงการ, ชื่อผู้ทำ, สถาบัน/องค์กร, วันที่นำเสนอ
*(กรอกเองตามข้อมูลจริง)*

---

## สไลด์ 2 — ปัญหาและแรงจูงใจ (~45 วิ)
**หัวข้อ**: ทำไม "ฝุ่นบนแผงโซลาร์" ถึงเป็นปัญหา

- ฝุ่นสะสม (soiling) บนแผงโซลาร์ลดประสิทธิภาพการผลิตไฟฟ้าอย่างมีนัยสำคัญ โดยเฉพาะในไทยที่มีทั้งฝุ่น PM2.5 สูงและฤดูแล้งยาว
- งานวิจัยไทย (11 โรงไฟฟ้า 10 จังหวัด, 1 ปี): optical transmission loss **เกิน 40% ที่พีค** ช่วงหน้าแล้ง
- เทียบภูมิภาค: มาเลเซีย ~0.15-0.20%/วัน, สิงคโปร์ ~0.057%/วัน — แต่ละพื้นที่ต่างกันตามฝุ่น/ฝนจริง ไม่มีค่าคงที่สากล
- **คำถามหลัก**: ควรล้างแผงเมื่อไหร่ถึงจะคุ้มค่าที่สุด — ล้างบ่อยเกินไปเสียค่าจ้าง ล้างช้าเกินไปเสียค่าไฟที่หายไป

---

## สไลด์ 3 — ระบบที่มีอยู่และปัญหาที่ระบุ (~45 วิ)
**หัวข้อ**: วิธีทำงานแบบเดิม vs ช่องว่างที่พบ

- ปัจจุบัน: ล้างแผงตาม**ตารางเวลาคงที่** (เช่น ทุก 1-3 เดือน) หรือกะประมาณจากประสบการณ์ ไม่ได้อิงข้อมูลฝุ่น/ฝนจริงของแต่ละวัน
- ปัญหา: ตารางคงที่ไม่ตอบสนองต่อสภาพจริง — ปีที่ฝนตกเยอะอาจล้างเกินจำเป็น (เสียเงินฟรี), ปีแล้งจัดอาจล้างช้าเกินไป (เสียไฟสะสมมาก)
- ไม่มีเครื่องมือที่ผสาน **ฝุ่นจริง + ฝนจริง + เศรษฐศาสตร์** เข้าด้วยกันเพื่อหาจุดคุ้มค่าแบบไดนามิก

---

## สไลด์ 4 — วัตถุประสงค์และผลลัพธ์ที่คาดหวัง (~30 วิ)
**หัวข้อ**: เป้าหมายของโปรเจค

- สร้างระบบแนะนำ**วันล้างแผงที่คุ้มค่าทางเศรษฐศาสตร์ที่สุด** โดยใช้แบบจำลองฟิสิกส์สำเร็จรูป (ไม่เทรน ML เอง เพราะยังไม่มีข้อมูล ground-truth ของไซต์เฉพาะ)
- ผลลัพธ์ที่คาดหวัง: แดชบอร์ดที่ใช้งานได้จริง แสดงคำแนะนำวันล้างแผง + มูลค่าเงินที่ประหยัดได้ อัปเดตทุกวันจากข้อมูลจริง

---

## สไลด์ 5 — แนวทางที่เลือกในการแก้ปัญหา (~45 วิ)
**หัวข้อ**: ทำไมเลือกทางนี้

- **ปฏิเสธแนวทาง custom ML model** — ไม่มีข้อมูลผลผลิตจริงของไซต์มาเทรน/ตรวจสอบ การเทรนโดยไม่มี ground truth เสี่ยง overfit/ผิดโดยไม่รู้ตัว
- **เลือกแบบจำลองฟิสิกส์ที่ผ่านการพิสูจน์แล้วในงานวิจัย**: `pvlib.soiling.hsu` (ขับเคลื่อนจากฝุ่น+ฝนจริง ไม่ใช่อัตราคงที่ที่เดาเอง) + PVWatts (พลังงาน)
- เปรียบเทียบกับ Kimber model (อีกโมเดลที่พิจารณา) — HSU คำนวณอัตราสกปรกจากฟิสิกส์จริง ไม่ต้องตั้ง `soiling_loss_rate` มือเหมือน Kimber

---

## สไลด์ 6 — แหล่งข้อมูลและขั้นตอนวิศวกรรม (~60 วิ)
**หัวข้อ**: Data Pipeline

**แหล่งข้อมูล (ทั้งหมดฟรี ไม่ต้องขอ API key ยกเว้นที่ระบุ):**
| ข้อมูล | แหล่ง |
|---|---|
| อากาศ + แสง (พยากรณ์/ย้อนหลัง) | Open-Meteo |
| ฝุ่น PM2.5/PM10 ดิบ | Open-Meteo (CAMS Global) |
| ฝุ่นจริง (ปรับเทียบ) | Air4Thai (เรียลไทม์) + PCD Open Data (ย้อนหลัง) |
| ฝนจริง (ตรวจสอบ) | กรมอุตุนิยมวิทยา (TMD) — 116 สถานีทั่วประเทศ |

**ขั้นตอน**: ดึงข้อมูล → คำนวณอัตราความสะอาดแผง (HSU) → คำนวณพลังงานที่ควรผลิตได้ (PVWatts) → หาวันล้างที่คุ้มค่าที่สุด (Economic Optimization) → แสดงผลบนแดชบอร์ด อัปเดตทุกวัน

---

## สไลด์ 7 — การพัฒนาและตรวจสอบแบบจำลอง (~90 วิ, เนื้อหาหลัก)
**หัวข้อ**: Model Calibration & Validation

จุดขายของโปรเจคนี้คือ**การตรวจสอบ/ปรับเทียบแบบจำลองด้วยข้อมูลจริงอย่างเข้มงวด** ไม่ใช่ใช้ค่า default เฉยๆ:

1. **Calibration**: ค่า default ของ pvlib ให้อัตราสกปรกแค่ ~0.017%/วัน (ต่ำกว่าจริง 6-20 เท่า) → ปรับเทียบกับงานวิจัยภูมิภาค (คาลิเบรทด้วยช่วงหน้าแล้งเพื่อเลี่ยง bias ตามฤดูกาล) → ได้ ~0.17%/วัน (หน้าแล้ง), ~0.12%/วัน (หน้าฝน) ตรงกับงานวิจัยมาเลเซีย
2. **Validation มุมเอียงแผง**: ทดสอบข้อมูลจริงเต็มปี 2025 (8,760 ชั่วโมง) พบมุมที่ดีที่สุด = 15° ตรงกับมาตรฐานอุตสาหกรรมไทย (10-15°) — ยืนยันว่าฟิสิกส์คำนวณตำแหน่งดวงอาทิตย์ถูกต้อง
3. **เกณฑ์ฝนล้างแผง**: เปลี่ยนจากเช็ครายวันเป็น**รายชั่วโมง** ตามงานวิจัย Norde Santos et al. 2024 (Solar RRL) — แยกพายุฝนแรงช่วงสั้นออกจากฝนปรอยที่ไม่ล้างแผงจริง
4. **Cross-validation กับแหล่งอิสระ**: เทียบ Open-Meteo กับ NASA POWER (ดาวเทียม) — MAE 16%, ไม่มี bias เชิงระบบ ยืนยันความน่าเชื่อถือ
5. **ระบบยืนยัน/แก้ไขด้วยข้อมูลจริงรายวัน**: ต่อ Air4Thai (ฝุ่น) + TMD (ฝน) เข้าระบบเพื่อแก้ไขค่าพยากรณ์ที่ผิดโดยอัตโนมัติทุกเช้า — พร้อม log บันทึกถาวรกันข้อมูลย้อนกลับผิด

---

## สไลด์ 8 — การสาธิต: แดชบอร์ด (~90 วิ, DEMO LIVE หรือ screenshot)
**หัวข้อ**: ระบบแนะนำวันล้างแผงโซลาร์เซลล์

- Streamlit dashboard, 3 แท็บ: **ภาพรวม** (ใช้งานจริง, ไม่มี jargon) / **รายละเอียดเศรษฐศาสตร์** / **เกี่ยวกับโมเดล** (โปร่งใสเต็มรูปแบบ)
- แสดงสด: KPI สถานะปัจจุบัน (ฝุ่น/ฝน/ความสะอาดแผง/พลังงาน), คำแนะนำวันล้าง + มูลค่าที่ประหยัดได้, กราฟความสะอาดแผงเทียบฝุ่น+ฝนตามเวลา, กราฟต้นทุนเทียบวันหลังล้าง (ACR)
- ปรับพารามิเตอร์ได้ตามสเปกระบบจริง (ขนาด kWp, มุมเอียง, ประสิทธิภาพระบบ, ค่าสัมประสิทธิ์อุณหภูมิ, ราคาไฟ/ค่าล้าง)

*(แนะนำ: เปิดแดชบอร์ดจริงสาธิตสด 60-90 วิ แทน screenshot ถ้าเวลาเอื้ออำนวย)*

---

## สไลด์ 9 — ผลลัพธ์การปรับปรุงประสิทธิภาพ (~60 วิ, **สำคัญที่สุด**)
**หัวข้อ**: ระบบนี้ช่วยประหยัดได้เท่าไหร่

ตัวอย่างจริงจากระบบ 100 kWp (กรุงเทพฯ, ค่าไฟ 4 บาท/kWh, ค่าจ้างล้าง 15 บาท/kWp):

| ตัวชี้วัด | ค่า |
|---|---|
| วันล้างที่คุ้มค่าที่สุด | ทุก 43 วัน |
| ต้นทุนเฉลี่ยที่จุดคุ้มค่า | 74.85 บาท/วัน |
| **ประหยัดเทียบกับไม่ล้างเลย** | **34.05 บาท/วัน** (~12,400 บาท/ปี) |
| ประหยัดเทียบกับล้างทุกวัน (กรณีสุดโต่ง) | 1,430 บาท/วัน |

**ประเด็นสำคัญที่ต้องพูดตรงๆ**: ตัวเลขนี้อิงราคาไฟ/ค่าล้าง**สมมติ** (รอข้อมูลจริงจากไซต์) — แต่ตัว**วิธีคิด/สูตรเศรษฐศาสตร์** (ACR — Average Cost Rate) ใช้ได้จริงทันทีที่ใส่ตัวเลขจริงของแต่ละไซต์

---

## สไลด์ 10 — ความเป็นไปได้ทางเศรษฐกิจและมูลค่าทางธุรกิจ (~45 วิ)
**หัวข้อ**: Business Case

- สูตร ACR(T) = ต้นทุนค่าล้างเฉลี่ย/วัน + มูลค่าไฟที่เสียเฉลี่ย/วัน → หาจุดต่ำสุด
- ปรับได้ตามไซต์จริง: ขนาดระบบ, ราคาไฟ (FiT/net-metering/ราคาขายส่ง), ค่าจ้างล้างแผงจริง
- ใช้ได้กับ**ทุกขนาดระบบ** ตั้งแต่ rooftop บ้านจนถึงโรงไฟฟ้าโซลาร์ฟาร์ม (ปรับแค่ kWp)
- ROI ของตัวระบบเอง: ต้นทุนพัฒนา ~0 (ใช้ open data + open-source library ทั้งหมด) เทียบกับมูลค่าที่ประหยัดได้ต่อปี

---

## สไลด์ 11 — ความยั่งยืนและการลดคาร์บอน (~30-45 วิ)
**หัวข้อ**: Sustainability Impact

- พลังงานที่ไม่สูญเสียจากฝุ่น = ผลิตไฟฟ้าสะอาดได้เต็มศักยภาพมากขึ้น → ลดการพึ่งพาไฟฟ้าจากเชื้อเพลิงฟอสซิลทดแทน (grid mix ไทยยังมีก๊าซ/ถ่านหินเป็นส่วนใหญ่)
- ล้างแผง**เท่าที่จำเป็นจริง** (ไม่ใช่ตามตารางคงที่) = ประหยัดน้ำที่ใช้ล้าง + ลดการเดินทางของทีมล้างแผง (ลด carbon footprint ทางอ้อม)
- *(ถ้ามีตัวเลข carbon factor ของไทย เช่น kgCO2/kWh จาก EGAT สามารถแปลง kWh ที่ประหยัดได้เป็นตัวเลข CO2 ที่ลดได้จริง — ยังไม่ได้ทำในโปรเจคนี้ ใส่เป็นข้อเสนอต่อยอดได้)*

---

## สไลด์ 12 — ความเสี่ยง ข้อจำกัด และความปลอดภัยไซเบอร์ (~45-60 วิ)
**หัวข้อ**: ข้อจำกัดที่ต้องรู้ก่อนนำไปใช้จริง

**ข้อจำกัดแบบจำลอง:**
- การล้างแผงจากฝนเป็นแบบ all-or-nothing ต่อชั่วโมง ไม่มีล้างบางส่วน
- `deposition velocity` ปรับเทียบกับค่าเฉลี่ยภูมิภาค ยังไม่ใช่ข้อมูลผลผลิตจริงของไซต์นี้โดยเฉพาะ (ยังไม่มีข้อมูลนั้น)
- ฝนพยากรณ์ผิดได้ — มีระบบยืนยัน/แก้ไขอัตโนมัติทุกเช้า แต่ยังมี delay 1 วัน

**ความเสี่ยงด้าน data/cyber:**
- พึ่งพา API ภายนอก 3 เจ้า (Open-Meteo, Air4Thai, TMD) — ถ้าล่มพร้อมกันระบบหยุดทำงานชั่วคราว
- ใช้ demo/shared credential ของ TMD (ไม่ใช่ production key ส่วนตัว) — ควรขอ personal API key ก่อนใช้งานจริงจัง
- ไม่มีข้อมูลส่วนบุคคล (PII) ในระบบ — ข้อมูลทั้งหมดเป็น public open data

---

## สไลด์ 13 — สรุปและข้อเสนอแนะ + แผนพัฒนาอนาคต (~45-60 วิ)
**หัวข้อ**: สรุป + Roadmap

**สรุป**: สร้างระบบแนะนำวันล้างแผงโซลาร์ที่ใช้แบบจำลองฟิสิกส์ + ข้อมูลจริงหลายแหล่ง (Open-Meteo/Air4Thai/TMD) พร้อมกลไกตรวจสอบตัวเองอัตโนมัติ ได้แดชบอร์ดที่ใช้งานได้จริง

**งานต่อยอด (เรียงตามศักยภาพ):**
1. **ข้อมูลผลผลิตจริงของไซต์** — เพื่อ calibrate `deposition_velocity` ให้เฉพาะเจาะจงไซต์ แทนค่าเฉลี่ยภูมิภาค
2. **ThaiWater/HII** (950 สถานีวัดฝนจริง) — แม่นกว่า TMD แต่ API ยังเข้าถึงยาก ต้องศึกษาเพิ่ม
3. **Solcast** — satellite irradiance nowcast แม่นกว่า Open-Meteo forecast (ต้องสมัคร key)
4. **กรมชลประทาน (RID)** — มี API แบบเปิดจริง (พิสูจน์แล้วจากข้อมูลเขื่อน) น่าจะมีข้อมูลฝนที่ยังไม่เจอ endpoint
5. ขยายรองรับ carbon accounting (kgCO2 ที่ลดได้จริง)
